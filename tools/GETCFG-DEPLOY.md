# Инвентаризация ПК домена (getcfg) — развёртывание

Собирает конфигурацию всех ПК домена в раздел «Рабочие станции» панели.
ПК не ходят в интернет: пишут файл в общую папку, а один хост-ретранслятор
(на нём уже стоит агент WinServ) пересылает данные в панель.

```
ПК по GPO ──SMB──►  \\RELAY\winserv-inv$  ──агент раз в минуту──►  панель WinServ
getcfg.ps1          (локальная папка на           /api/workstations/report
                     ретрансляторе)
```

## 1. Ретранслятор и папка-дроп

Выберите хост в домене, где **уже работает агент WinServ** и который имеет выход
на сервер (обычно это DC или файловый сервер — например DC01). На нём:

1. Создайте локальную папку, например `C:\winserv-inv`.
2. Опубликуйте её как **скрытую** SMB-шару `winserv-inv$`. Права на **шару** и
   **NTFS** (Change / Modify) выдайте тем, от чьего имени будет работать GPO-скрипт:
   - **`Domain Computers`** — если скрипт запускается как **Startup** (от SYSTEM,
     рекомендуется: полный доступ к железу и SMART);
   - **`Domain Users`** — если как **Logon** (от пользователя).

   Права на чтение/список рядовым пользователям можно не давать — скрипт только
   создаёт/заменяет собственный файл.

## 2. Включить ретранслятор в панели

Серверы → у выбранного хоста **Edit** → блок «Инвентаризация ПК» →
включите **«Ретранслятор инвентаря»** и укажите **локальный** путь папки
(`C:\winserv-inv`, не UNC — агент читает её локально). Сохраните.

В течение минуты агент начнёт забирать файлы из папки, пересылать их и удалять
только те, что сервер подтвердил.

## 3. GPO-скрипт на все ПК

1. Скопируйте `tools/getcfg.ps1` в `\\<домен>\NETLOGON\getcfg.ps1`.
2. Откройте его и задайте `$DropShare` = ваша шара (`\\DC01\winserv-inv$`),
   либо передавайте параметром в GPO.
3. Создайте GPO на нужный OU:
   - **Рекомендуется:** Computer Configuration → Policies → Windows Settings →
     Scripts → **Startup** → вкладка **PowerShell Scripts** → Add:
     - Script Name: `\\<домен>\NETLOGON\getcfg.ps1`
     - Parameters: `-DropShare \\DC01\winserv-inv$`
   - Либо Logon-скрипт (User Configuration) — тогда пишется реальный пользователь.
4. Убедитесь, что политика PowerShell позволяет запуск (GPO-скрипты Startup
   выполняются в обход ExecutionPolicy; при необходимости — RemoteSigned).

Скрипт **только читает** систему, ничего не меняет. Данные обновляются при каждом
запуске (загрузка/вход). Для регулярного обновления без перезагрузок можно
добавить запланированную задачу через GPO (Scheduled Task, раз в сутки), вызывающую
тот же скрипт.

## Что собирается

Железо (модель, серийник, CPU, RAM, шасси), ОС и сборка, диски (объём, свободно,
тип, SMART-здоровье), мониторы (модель и серийник из EDID), сеть (IP/MAC),
последний пользователь, домен/OU/сайт AD, установленное ПО, последние патчи (KB).

## Идентификация и клоны

ПК опознаётся по **MachineGuid** (не по имени — имя можно менять). Если парк
разворачивался из образа **без sysprep**, несколько машин имеют одинаковый
MachineGuid; они различаются по серийному номеру BIOS и помечаются в панели как
**«клон»**. Правильное решение — `sysprep /generalize` при захвате образа, чтобы
каждая установка получала свой MachineGuid.

## Проверка

- Файлы появляются в папке-дропе и **исчезают** через минуту (их забрал агент).
- В панели раздел «Рабочие станции» наполняется.
- Битые/недописанные файлы ретранслятор откладывает как `*.json.bad` — при
  массовом появлении смотрите Event Log ПК, источник `WinServGetCfg`.
